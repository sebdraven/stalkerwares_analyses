# iKeyMonitor v19.1 — Full lab walkthrough (validated 2026-09-09)

End-to-end procedure that brings a real iKeyMonitor v19.1 sample under full mock-C2
control on Corellium — **both the REST channel and the real-time WebSocket channel**.

Everything below was executed and verified on a Corellium Android 13 device. It
supersedes the generic setup in `README.md` §5 wherever they differ (the README
was written before the live run; this file is the ground truth).

> Research use only. Sample: `ikm-android-weeklybuild.apk`,
> package `com.android.internet.a20251031` (v19.1).

---

## 0. Result

The mock C2 drives the stalkerware on both channels:

- **REST**: `register` accepted (`Ret=300`), the app adopts our mock license
  (`MOCK-LICENSE-2026`) and UnitID (`MSIK-ONLINE-MOCK001`), stable `cycle` heartbeat.
- **WebSocket (WSS)**: the app connects to our `/ws`, sends its handshake, is
  identified with the mock license, and accepts real-time commands
  (screenshot / camera / surrounding).
- Oracle confirmed: `KEY_ILoginStatusogs` flips to `true` in the app prefs
  (the `<LoginStatus>1</LoginStatus>` was parsed and persisted).

## 1. Corellium device

- **Create Device** → **Android 13.0.0 (r84 userdebug)**, ARM.
  - Android 13 matches the APK's `compileSdk 33` and keeps the **classic system
    CA store** (`/system/etc/security/cacerts/`). Android ≥14 moves it to an APEX
    module (`/apex/com.android.conscrypt/cacerts/`), which is more painful.
- **Tick "Enable WAN access"** at creation. Without it the device has no validated
  default network (`Active default network: none`) and the app blocks on
  "no internet" before ever contacting the C2.
- Device is **root by default**, prompt `root:/#`.

First check after boot:
```bash
adb shell dumpsys connectivity | grep "Active default"
# must be != none  (e.g. "Active default network: 100")
```

## 2. Connectivity: SSH tunnel → ADB → adb reverse

**Order matters: open the SSH tunnel BEFORE any `adb connect`.**

```bash
# 1. SSH tunnel (ADB port 5001). Do NOT add -M -Ssock (Warp injects it and it
#    fails with "unix_listener: cannot bind ... Function not implemented").
ssh -N -f -L 5001:<DEVICE_IP>:5001 <user>@proxy.corellium.com
#   <DEVICE_IP> = device internal IP from the Corellium console (e.g. 10.11.1.7)

# 2. Attach ADB
adb connect localhost:5001
adb devices          # -> localhost:5001   device
adb root
```

Reset between VMs:
```bash
adb kill-server
pkill -f proxy.corellium.com
# "offline" in `adb devices` = previous VM is dead
```

## 3. Expose the mock to the device — the PORT trap

The app pref `KEY_ser_addr` = `https://ikmws.awsapi.io` **without a port** → the app
hits **443**, not 8443. So reverse **both** ports (adbd is root on Corellium, the
privileged bind on 443 works):

```bash
adb reverse tcp:443  tcp:8443     # <-- the important one
adb reverse tcp:8443 tcp:8443
adb reverse tcp:1935 tcp:1935     # RTMP (optional)
adb reverse --list                # confirm tcp:443 and tcp:8443
```

The mock stays on 8443; the device reaches it over loopback via these reverses.

---

## 4. DNS: /etc/hosts → loopback

`/` is **read-only by default** on Corellium — remount rw first, every boot:

```bash
adb shell "mount -o rw,remount /"
adb shell "cat >> /etc/hosts << 'EOF'
127.0.0.1  ikmws.awsapi.io
127.0.0.1  ikmws-mirror.awsapi.io
127.0.0.1  ikm-sv2.awsapi.io
127.0.0.1  ikm-sv3.awsapi.io
127.0.0.1  ikm-sv4.awsapi.io
EOF"
adb shell cat /etc/hosts     # verify the 5 lines are present
```

Note: `nslookup` on Android does **not** read `/etc/hosts` (pure DNS tool) — do not
trust it. The real test is a `curl` from the device (§7).

## 5. TLS certificate (system store)

`openssl` is absent on the device → compute the hash on the Mac. The subject hash is
stable (`65afb59f`) as long as the cert subject doesn't change, so regenerating the
cert with the same fields keeps the same filename.

```bash
# On the Mac (in mock_c2/, cert.pem already generated by server.py)
openssl x509 -inform PEM -subject_hash_old -in cert.pem | head -1   # -> 65afb59f
adb push cert.pem /sdcard/ikm_mock.pem

# On the device (root, rw remounted)
adb shell "mount -o rw,remount / && \
  cp /sdcard/ikm_mock.pem /system/etc/security/cacerts/65afb59f.0 && \
  chmod 644 /system/etc/security/cacerts/65afb59f.0"
```

⚠️ Never run `server.py --regen-cert` after the cert is installed on the device — it
invalidates the installed cert. Just `uv run python server.py`.

## 8. Install and grant the APK

```bash
adb install -r ikm-android-weeklybuild.apk
```

Grant all runtime permissions + the ones the app's own checks require. **The key
one is `WRITE_EXTERNAL_STORAGE`**: the app's `x.e()` gate tests it, and it guards the
Client-ID generation, the license file load (`l1.j.g` / `l1.i.c`), and the storage
dirs. Without it the whole on-disk state is unreachable.

```bash
# storage gate (critical)
adb shell pm grant com.android.internet.a20251031 android.permission.WRITE_EXTERNAL_STORAGE

# exfil permissions
for P in READ_SMS READ_CONTACTS READ_CALL_LOG ACCESS_FINE_LOCATION RECORD_AUDIO CAMERA READ_CALENDAR ; do
  adb shell pm grant com.android.internet.a20251031 android.permission.$P
done

# accessibility (keylogger), notification listener, usage access, overlay, battery
adb shell settings put secure enabled_accessibility_services com.android.internet.a20251031/com.a_Xf1Mc3Fh6Tb0Bv1Od8Jv.A_0b5bb70f0f56008c14513534c171bea3
adb shell settings put secure accessibility_enabled 1
adb shell cmd notification allow_listener com.android.internet.a20251031/com.a_Xf1Mc3Fh6Tb0Bv1Od8Jv.A_ec724c8198bec96b81ff3cc31650beb9
adb shell appops set com.android.internet.a20251031 android:get_usage_stats allow
adb shell appops set com.android.internet.a20251031 SYSTEM_ALERT_WINDOW allow
adb shell dumpsys deviceidle whitelist +com.android.internet.a20251031
```

Note: the app's in-app "Configuration Check" wizard may still show red crosses
(Accessibility / Screenshot) because it does custom checks (`u.x.*`,
`h1.w.b` via `resolveServiceClassByReflection`) that ADB grants don't satisfy
visually — it does not block the background service or the C2. Clicks in the
Corellium GUI are often dead; drive the device with `adb shell input tap <x> <y>`,
`input keyevent`, `input text`, and open Android settings via
`am start -a android.settings.*`.

## 9. Register the app

Launch it:
```bash
adb shell monkey -p com.android.internet.a20251031 -c android.intent.category.LAUNCHER 1
```

On the `TrialPage` screen ("Enter your license key or email address"), type anything
(e.g. `test@test.com`) and press **REGISTER**. The mock replies `Ret=300` and the app
persists the license. You'll see `>>> [register] ... -> Ret=300` in the mock, then a
steady `cycle` + `schedule_surround` heartbeat.

License persistence (for reference): the app writes an XML file
`/sdcard/Android/.bak/.com.android.internet.service/.device.data` with each field
DES/CBC/PKCS5-encrypted (key `&HOk-=&%`, IV `{1..8}`, base64). `forge_device_data.py`
reproduces this byte-for-byte.

## 10. Frida (push a real server — Corellium's native Frida is unreliable)

Corellium's built-in Frida leaves only `frida-helper-*.dex` and won't answer. Push a
matching `frida-server`:

```bash
# 1. version must match the client
uv run frida --version          # e.g. 17.17.0

# 2. download the ARM64 server for that exact version
curl -L -o frida-server.xz \
  "https://github.com/frida/frida/releases/download/17.17.0/frida-server-17.17.0-android-arm64.xz"
unxz frida-server.xz

# 3. push + run on a dedicated port (avoids the Corellium Frida conflict)
adb push frida-server /data/local/tmp/frida-server
adb shell chmod 755 /data/local/tmp/frida-server
adb shell "nohup /data/local/tmp/frida-server -l 0.0.0.0:27043 >/dev/null 2>&1 &"
adb shell "ps -A | grep frida-server"     # confirm it runs

# 4. reach it via adb forward (more reliable than the SSH tunnel for Frida)
adb forward tcp:27043 tcp:27043
uv run frida-ps -H 127.0.0.1:27043        # lists processes -> "Internet Service" = iKM
```

The iKM process is named **"Internet Service"** in `frida-ps`.

## 11. Unlock the WebSocket channel

The app only calls `get_websocket_address` when it receives the internal broadcast
`ACTION_.CHECK._WEBSOCKET` **and** several runtime conditions hold — one of them,
`e0.g.B()` (pref `KEY_SessionValue`), the app keeps clearing, so the natural
`onReceive` always bails out. The clean fix is to force the handler directly with
Frida.

`ikeymonitor_ws_unlock.js` instantiates the receiver and calls
`A_91ba….b(context)` (the `get_websocket_address` handler) after a short delay, and
traces the whole path.

```bash
uv run frida -H 127.0.0.1:27043 -n "Internet Service" -l ikeymonitor_ws_unlock.js
```

Within a few seconds you get, in the mock:
```
>>> [get_websocket_address] ... WS_ADDRESS requested -> wss://ikmws.awsapi.io/ws
WebSocket /ws [accepted]
WebSocket connected
Sent onConnect handshake
WS recv: <IKMService><RequestType>screen_video</RequestType>...<License>MOCK-LICENSE-2026</License>...
WS identified: client=020000000000
```

Confirm the oracle:
```bash
adb shell "cat /data/data/com.android.internet.a20251031/shared_prefs/Application.xml" | grep -i login
# KEY_ILoginStatusogs = true
```

Why Frida is needed here: the mock's REST replies are already correct
(`get_websocket_address` returns `<Ret>1</Ret>` + `<websocket_address>` +
`<LoginStatus>1</LoginStatus>`, all parsed fine by `x.u.a()`). The only missing
piece is triggering the handler, gated by app-side runtime state that a REST mock
can't satisfy. Forcing `A_91ba….b()` bypasses that gate.

## 13. Key facts learned (for the talk / next samples)

- The **port trap** (443 vs 8443, no port in `KEY_ser_addr`) is the first silent
  blocker.
- **WAN access** is mandatory for the app's connectivity self-check, even though all
  C2 traffic goes over loopback.
- The app has a **layered gate on storage** (`x.e()` = `WRITE_EXTERNAL_STORAGE`) that
  cascades into Client-ID, license load, and directory creation.
- License is persisted as **DES/CBC XML** (`.device.data`), reproducible with
  `forge_device_data.py` (our forged `<lic>` == the on-device one, byte-for-byte).
- The **WS channel is gated behind an internal broadcast + volatile session pref**;
  Frida forcing `A_91ba….b()` is the reliable trigger.
- The app's WebSocket is **not OkHttp3** (ClassNotFoundException) — a different WS lib.
- Corellium **GUI clicks are unreliable**; drive everything via `adb`.
- Corellium **native Frida is broken**; push a matching `frida-server` and use
  `adb forward` on a dedicated port.
